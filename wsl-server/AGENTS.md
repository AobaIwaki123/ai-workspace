# WSL サーバー構築・運用手順 規約 (AGENTS.md)

このワークスペースは、Windows 上の WSL（Windows Subsystem for Linux）を活用したサーバー環境構築、ネットワーク・自動起動設計、および最終的な「単一の統合手順書（Runbook）」の策定を推進するための協業領域です。

---

## ディレクトリ構成と役割

```
wsl-server/
├── AGENTS.md             # 本規約ファイル（スコープ・開発ルール・記載方針）
├── discussion.md         # 議論の方向性、要件定義、ロードマップ、進捗管理
├── note/                 # 調査・検証・各フェーズの技術メモ（01_xxx.md 形式で蓄積）
│   └── 01_requirements_and_architecture.md # 要件定義と全体アーキテクチャ設計
├── adr/                  # 確定した方針・アーキテクチャ選定 (0001-xxx.md)
└── scripts/              # セットアップスクリプト・自動化ツール・検証コマンド
```

---

## 運用ルール

1. **進捗・議論の記録 (`discussion.md`)**
   - 目的、前提条件、ロードマップ、各タスクのステータスを常に最新に保ちます。
2. **知見の蓄積 (`note/`)**
   - Windows / WSL 特有の仕様（ネットワークモード、systemd、ポート転送、Windows起動時の自動起動等）や検証結果は `note/` に連番付きでドキュメント化します。
3. **意思決定の記録 (`adr/`)**
   - ネットワーク構成（Mirrored Mode vs NAT）、自動起動方式（Windowsタスクスケジューラ vs systemd）、ストレージ配置などの重要選定理由は `adr/` に記録します。
4. **再現性の確保 (`scripts/`)**
   - 検証したコマンド列や環境構築処理は可能な限り自動化スクリプトとして `scripts/` に蓄積し、手順書のコピペミスを防ぎます。
5. **最終ゴール（統合手順書の作成）**
   - 各フェーズでの検証結果と確定手順を統合し、誰でも最初から最後まで再現可能な「単一のWSLサーバー構築手順書」として完成させます。

## ドキュメント記述規約

- 本ワークスペース内のすべてのドキュメントにおいて、原則として絵文字（emoji）は使用せず、プロフェッショナルでクリーンなテキストスタイルを維持します。
- ターミナル（CLI）上での可読性低下を防ぐため、**ユーザーへのチャット返答本文には生の Mermaid コードブロック（` ```mermaid ... ``` `）を直接出力しません**（Markdown ドキュメント内でのみ記述し、チャット本文からはリンクと要約のみを提示します）。
- Markdown ドキュメント内で Mermaid 構文を使用する際は、構文エラーを防ぐため特殊文字を必ずダブルクォート（`"..."`）でエスケープします。
