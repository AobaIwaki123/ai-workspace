# 当日タイムライン＆完全チェックリスト (05_checklist.md)

ISUCON当日のタイムスケジュールと、フェーズごとの必須アクションチェックリストです。

---

## ⏰ 当日タイムスケジュール例 (10:00〜18:00)

```
10:00 - 10:30 (0.5h) : サーバーログイン、初期ベンチマーク、Git化、計測環境構築、マニュアル熟読
10:30 - 12:30 (2.0h) : 初手改善（Nginx/MySQL設定、ログ計測、スロークエリIndex追加）
12:30 - 16:30 (4.0h) : メイン改善（N+1解消、インメモリキャッシュ、複数台構成への分散）
16:30 - 17:30 (1.0h) : 仕上げ（全台ログOFF、最終チューニング、安定性確認）
17:30 - 18:00 (0.5h) : 【最重要】再起動試験 & 最終スコア記録（コード凍結）
```

---

## 📋 フェーズ別チェックリスト

### 1. 開始直後フェーズ (10:00 - 10:30)

- [ ] **サーバーへSSHログイン**: 全台（通常3台）にログインできるか確認
- [ ] **初期状態の確認**:
  - `uname -a`, `cat /etc/os-release` (OS確認)
  - `nproc`, `free -m`, `df -h` (スペック・ディスク容量確認)
  - `systemctl list-unit-files --type=service | grep running` (稼働サービス確認)
- [ ] **マニュアル・レギュレーションの熟読**:
  - 何のサービスか？（例: 配信プラットフォーム、ライブコマース等）
  - ベンチマークの加点・減点ルール
  - キャッシュや遅延の許容度
  - 使用ポート、禁止事項
- [ ] **初期ベンチマーク実行**:
  - 初期スコアを記録（これより下がったらロールバック）
- [ ] **Git初期化 & バックアップ**:
  - `/etc/nginx`, `/etc/mysql`, `/home/isucon/webapp` などをGit管理下に置く
  - リモートリポジトリ（GitHub private等）へPush
- [ ] **計測ツールの配備**:
  - `alp` のバイナリ配置
  - Nginx の LTSV ログフォーマット設定
  - MySQL のスロークエリログ有効化 (`long_query_time = 0.0`)
- [ ] **初手ベンチマーク & ベースライン計測**:
  - `alp` と `pt-query-digest` を実行し、初期ボトルネックを特定

---

### 2. 改善サイクルフェーズ (10:30 - 16:30)

- [ ] **サイクル手順の徹底**:
  1. `git pull` で最新コードを確認
  2. alp / pt-query-digest でワースト1の箇所を特定
  3. 仮説を立てて修正（1イテレーション1修正）
  4. ビルド＆デプロイ
  5. ログクリアしてベンチマーク実行
  6. **スコア上昇 & PASS** → `git commit & push`
  7. **FAIL またはスコア低下** → 即座に `git revert` して再ベンチ
- [ ] **定番改善の適用**:
  - [ ] Nginx: 静的ファイルの直接配信 (`Cache-Control`, `expires`)
  - [ ] MySQL: `innodb_buffer_pool_size` (メモリの60〜70%), `innodb_flush_log_at_trx_commit = 2`
  - [ ] MySQL: スロークエリへの適切な複合インデックス
  - [ ] App: N+1 の IN句 / JOIN 化
  - [ ] App: 頻出リードデータのインメモリキャッシュ / SingleFlight
  - [ ] Infra: 複数台（3台）への負荷分散（Server1: Nginx+App / Server2: App / Server3: MySQL 等）

---

### 3. 終了前・再起動試験フェーズ (17:00 - 18:00)

> [!CAUTION]
> 17:30以降は **絶対に新しい大きな機能修正を入れない（コードフリーズ）**。

- [ ] **ログの無効化 (17:00 - 17:30)**:
  - [ ] Nginx の `access_log off;` または通常形式に変更
  - [ ] MySQL の `slow_query_log = 0`
  - [ ] アプリケーションのデバッグログ出力停止
  - [ ] pprof などのプロファイラポートの無効化（レギュレーションによる）
  - [ ] ログ停止状態でベンチマーク実行（ここでスコアが1.5〜2倍跳ね上がることが多い）
- [ ] **再起動試験 (17:30 - 17:50)**:
  - [ ] 全台のサーバーを再起動: `sudo reboot`
  - [ ] サーバー起動後、SSHで入れるか確認
  - [ ] 全サービス（Nginx, MySQL, App）が自動起動 (`systemctl is-active`) しているか確認
  - [ ] ベンチマークを実行し、**PASS して高スコアが出ることを確認**
- [ ] **最終確認 (17:50 - 18:00)**:
  - [ ] 不要なプロセス・ポートが開いていないか
  - [ ] 提出用の必要情報（スコア、リポジトリ等）を確認
