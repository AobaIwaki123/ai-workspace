# 0001: Zeitgeist CLI アーキテクチャ選定（Adapter パターンと外部設定駆動）

## ステータス
Accepted

## 背景と動機
- 日々の情報収集や日常会話・コミュニケーションの話題として活用するため、映画、音楽、漫画、エンタメなどの最新トレンド情報を効率的かつ機械的に集約する仕組みが必要となった。
- LLMに生のWebブラウジングを行わせるとトークン消費が莫大になり、構造変更時のハルシネーションやスクレイピング失敗のリスクが高い。
- 利用者ごとの関心に応じた媒体リスト（対象URLやカテゴリ）を個人環境で自由に管理・秘匿したい一方、CLIのソースコード自体は汎用的なマルチソース・アグリゲーターとしてPublic/OSS成果物にしたいという要件があった。

## 意思決定 (Architecture Decision)

1. **Goによる単一バイナリCLIの実装 (`cmd/zeitgeist`)**:
   - 高速な並行処理（Goroutine/Semaphore）により、複数媒体を1秒未満で一括取得する。
   - `stdout` にはAIおよび他ツールがそのまま食えるクリーンな構造化JSONを出力し、ログはすべて `stderr` に `log/slog` で出力する（UNIX哲学の遵守）。

2. **Adapter Pattern（取得ドライバーの抽象化）**:
   - 媒体定義（Source）と取得実装（Driver）を分離。
   - `RSSDriver`（汎用RSS/Atom）、`HTMLSelectorDriver`、専用スクレイパー等を `Driver` インターフェースで統一管理し、設定ファイルの `driver: rss` 指定で同一エンジンを使い回す。

3. **Config-Driven による Public/Private の完全分離**:
   - コード本体 (`space/zeitgeist`) はPublicなOSS成果物とし、デフォルト設定 (`configs/sources.sample.yaml`) には無害な一般フィードのみを配置。
   - ユーザーのプライベートな媒体リストは `private/data/zeitgeist/sources.yaml` に配置し、実行時に `-config` 引数で動的に注入する。

4. **トークン保護とHTMLサニタイズ**:
   - 取得テキストからHTMLタグを正規表現で完全除去し、HTML実体参照をデコード。
   - スニペットは最大200文字に制限し、AIに入力した際のトークン消費を最小化する。

5. **部分故障の許容（Graceful Degradation）**:
   - 単一媒体が404やタイムアウトで失敗してもCLI全体をクラッシュさせず、結果オブジェクトの `error` フィールドに隔離して他媒体のデータを必ず出力する。

## メリット
- トークン消費量を90%以上削減しつつ、常に最新のトレンド生データをAIへ供給可能。
- 媒体リストの復元・管理が `private/` サブモジュール内で永続化され、コードも公開可能。
- 媒体追加が設定ファイルのYAML追記のみで完結（ノーコード）。

## デメリット / トレードオフ
- RSSが提供されていない媒体（Instagramや一部Webサイト）については、将来的に専用のHTMLスクレイパーや外部APIドライバーを追加実装する必要がある。
