# データベーススペシャリスト基礎知識体系チェックリスト

## 概要

本ドキュメントは、IPA（情報処理推進機構）データベーススペシャリスト試験（DB）の午前IIおよび午後試験の基礎となる重要理論・技術用語・設計原則を体系的に整理した知識リストです。

---

## 1. 関係データモデルと関係代数

関係モデル（Relational Model）は、データを「関係（Relation：テーブル）」と「組（Tuple：行）」、「属性（Attribute：列）」の集合として表現する数学的モデルです。

### 1.1 関係代数演算の基本

| 演算名 | 記号 / 概念 | 内容・定義 | SQL対応 |
| :--- | :--- | :--- | :--- |
| **射影 (Projection)** | $\pi$ | 指定した特定の属性（列）のみを抽出する演算。重複行は排除される。 | `SELECT DISTINCT col1, col2` |
| **選択 (Selection)** | $\sigma$ | 指定した条件を満たす組（行）のみを抽出する演算。 | `SELECT * WHERE condition` |
| **直積 (Cartesian Product)** | $\times$ | 2つの関係の全行のあらゆる組み合わせ（$M \times N$ 行）を生成する。 | `CROSS JOIN` または `FROM T1, T2` |
| **等結合 (Equi-Join)** | $\bowtie_{A=B}$ | 共通の属性値が一致する組同士を結合する演算。 | `INNER JOIN ON T1.A = T2.B` |
| **自然結合 (Natural Join)** | $\bowtie$ | 同名の属性同士で等結合を行い、重複する属性列を1つにまとめた演算。 | `NATURAL JOIN` |
| **商 (Division)** | $\div$ | 関係Rのうち、関係Sのすべての組との組み合わせを持つ組を抽出する演算。 | 「すべての〜を満たす」相関サブクエリ（`NOT EXISTS` 2重等） |
| **和 (Union)** | $\cup$ | 2つの関係に含まれる組を合わせた関係（重複排除）。属性数が等しく定義域が互換である必要あり。 | `UNION` |
| **差 (Difference)** | $-$ | 関係Rに含まれ、関係Sに含まれない組を抽出する。 | `EXCEPT` (または `MINUS`) |

## 2. 関数従属と正規化理論

データの冗長性を排除し、更新時・挿入時・削除時の不整合（更新時異状）を防ぐための論理設計理論です。

### 2.1 関数従属（Functional Dependency: FD）の分類

- **完全関数従属 (Full Functional Dependency)**:
  主キーの一部ではなく、主キー全体によってのみ属性値が一意に決定される関係。
- **部分関数従属 (Partial Functional Dependency)**:
  複合主キーの一部（真部分集合）によって属性値が決定されてしまう関係。
- **推移的関数従属 (Transitive Functional Dependency)**:
  主キー以外の非キー属性 $X$ によって別の非キー属性 $Y$ が決定される関係（$PK \to X \to Y$）。

### 2.2 正規形の定義と判断基準

| 正規形 | 達成要件 | 分離・排除される異状 |
| :--- | :--- | :--- |
| **非正規形** | 繰り返し項目や配列、構造体を含む表。 | データの重複、行ごとの構造の不均一。 |
| **第1正規形 (1NF)** | すべての属性値が単一の値（原子値: Atomic Value）である。繰り返し項目を排除。 | 繰り返しグループの排除。 |
| **第2正規形 (2NF)** | 第1正規形であり、かつ主キーに対する**部分関数従属を排除**（すべての非キー属性が主キーに完全関数従属）。 | 複合主キーの一部に依存する情報の更新異状を排除。 |
| **第3正規形 (3NF)** | 第2正規形であり、かつ主キー以外の属性への**推移的関数従属を排除**。 | 非キー属性間の従属による更新異状を排除。 |
| **ボイス・コッド正規形 (BCNF)** | 決定項（矢印の左側）がすべて候補キー（スーパーキー）である状態。 | 主キー候補が複数交差する場合の従属異状を排除。 |

## 3. トランザクション管理と同時実行制御

### 3.1 ACID特性

| 特性 | 英名 | 内容 | 実装・保証技術 |
| :--- | :--- | :--- | :--- |
| **原子性** | Atomicity | トランザクション内の処理が「すべて実行される」か「すべて取り消される（All or Nothing）」こと。 | ロールバック、先行書き込みログ（WAL） |
| **一貫性** | Consistency | 実行前後でデータベースの整合性制約（一意性、参照整合性、CHECK制約等）が保たれること。 | 制約チェック、トリガー |
| **独立性 (隔離性)** | Isolation | 同時に実行される複数のトランザクションが互いに干渉せず、順番に実行された場合と同じ結果になること。 | ロック機構、MVCC（多版同時実行制御） |
| **永続性** | Durability | コミットが完了したトランザクションの結果は、その後のシステム障害でも失われないこと。 | チェックポイント、REDOログ、WAL |

### 3.2 同時実行制御と排他制御

- **ロックの種類**:
  - **共有ロック (Shared Lock / Sロック)**: 読み取り時に使用。複数トランザクションで共有可能。
  - **専有ロック (Exclusive Lock / Xロック)**: 更新時に使用。他トランザクションのSロック・Xロックを排除。
- **2相ロッキングプロトコル (Two-Phase Locking: 2PL)**:
  - ロック獲得のみを行う「成長相（Growing Phase）」と、ロック解放のみを行う「縮退相（Shrinking Phase）」に分離することで、**直列可能性（Serializability）**を理論的に保証する。
  - 2PLだけではデッドロックは防止できない。
- **デッドロック (Deadlock)**:
  - 複数のトランザクションが互いの保持する資源のロック解放を待ち続け、停止する状態。
  - 対策: 資源獲得順序の統一、タイムアウト検出、待ちグラフ（Wait-For Graph）による閉路検出とトランザクション強制アボート。

## 4. 障害回復技術（Crash Recovery）

### 4.1 ログ先行書き込み（Write-Ahead Logging: WAL）
データベースバッファ上の更新データをディスク上のデータファイルへ書き出す前に、必ず対応する更新ログをディスクへ先行して永続化する原則。

### 4.2 チェックポイントと回復手順（ARIES等）

- **REDO（ロールフォワード / 再実行）**:
  障害発生時に、コミット済みトランザクションの更新結果をログに基づいてデータファイルに再反映する。
- **UNDO（ロールバック / 取り消し）**:
  障害発生時に、未コミットだったトランザクションの更新結果をログの逆順で取り消し、トランザクション開始前の状態に戻す。

| 障害時の状態 | 処理内容 | 理由 |
| :--- | :--- | :--- |
| **チェックポイント前にコミット完了** | 処理不要（すでに反映済み） | データファイルに書き出し済みのため。 |
| **チェックポイント後にコミット完了** | **REDO（ロールフォワード）** | 永続性（Durability）を保証するため。 |
| **障害発生時点で未コミット** | **UNDO（ロールバック）** | 原子性（Atomicity）を保証するため。 |

## 5. 物理設計とインデックス

### 5.1 B+木インデックス（B+ Tree Index）
- リレーショナルデータベースで最も一般的に利用される木構造インデックス。
- **特徴**:
  - リーフノードのみに実データへのポインタ（または実データ）を保持し、リーフ同士が双方向リストで連結されている。
  - 完全平衡木（Balance Tree）であり、探索・挿入・削除の計算量が $O(\log N)$ で安定。
  - 等値検索（`=`）だけでなく、範囲検索（`BETWEEN`, `<`, `>`）やソート処理（`ORDER BY`）にも極めて有効。

### 5.2 ハッシュインデックス & ビットマップインデックス
- **ハッシュインデックス**: ハッシュテーブルを利用し、$O(1)$ で高速検索。等値比較のみ有効（範囲検索不可）。
- **ビットマップインデックス**: カーディナリティ（値の種類の少なさ：性別、フラグ等）が極端に低い列に有効。ビット演算（AND, OR）による高速な複数条件絞り込みが可能。
