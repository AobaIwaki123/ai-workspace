# データベーススペシャリスト試験（DB）学習・対策 規約 (AGENTS.md)

このワークスペースは、**データベーススペシャリスト試験（DB）学習・対策** に関する調査・設計・検証・自動化を推進するための協業領域です。

---

## ディレクトリ構成と役割

```
space/database-specialist/
├── AGENTS.md             # 本規約ファイル（スコープ・開発ルール）
├── discussion.md         # 議論の方向性、要件定義、進捗管理、アクションアイテム
├── note/                 # 調査・検証・技術メモ（01_xxx.md 形式で蓄積）
├── adr/                  # 確定した方針・アーキテクチャ選定 (0001-xxx.md)
└── scripts/              # 本テーマ専用のスクリプト・ツール・自動化コード
```

---

## 運用ルール

1. **進捗・議論の記録 (`discussion.md`)**
   - 議論の前提、目的、課題、ネクストアクションを常に最新に保ちます。
2. **知見の蓄積 (`note/`)**
   - 調査した仕様や技術検証の結果は `note/` に連番付きマークダウンで記録します。
3. **意思決定の記録 (`adr/`)**
   - 設計方針やアーキテクチャの選定理由は `adr/` に記録します。
4. **再現性の確保 (`scripts/`)**
   - 検証用スクリプトや実行手順は `scripts/` 配下にコード化して残します。

## 過去問壁打ち・導出過程解説プロトコル (Anti-Hallucination & Evidence-Based Coaching)

午後試験（記述・事例問題）の過去問演習や壁打ちを行う際は、AIが誤った解釈やハルシネーションを起こすことを完全に防止するため、以下の規約を厳格に遵守します。

1. **公式解答例・採点講評の絶対アンカー化**:
   - AI自律の推測や独自解釈による解答の創作を禁止します。
   - 必ずIPA公式の「解答例」および「採点講評（出題趣旨）」を所与の前提（確定事実）として固定し、そこに至る**「逆引きの導出プロセス」**を解説します。
2. **問題文の直接引用による根拠提示 (Evidence Integrity)**:
   - なぜそのエンティティ、主キー、外部キー、カーディナリティ（1対多、多対多等）になるのかを説明する際は、**必ず問題文中の該当記述（業務ルール）を直接引用**して論理の結合を示します。
3. **出題者の意図と誤答パターンの照合**:
   - IPA採点講評に記載されている「受験者が陥りやすかった誤答」「見落としがちな制約条件」を参照し、ユーザーの解答や疑問との差分を客観的に分析します。
4. **思考プロセスの段階的分解**:
   - 解説は単なる正解発表ではなく、「①業務要件のマーキング」→「②候補エンティティ・属性の抽出」→「③関数従属・カーディナリティの確定」→「④関係スキーマ・ER図への反映」の標準手順に沿って分解して提示します。

## 過去問アセットのオンデマンド拡充規約 (On-Demand Asset Fetching & Expansion)

トークン消費の最適化と確実な記憶（永続化）を両立するため、過去問アセットは以下のルールに従って段階的に拡充します。

1. **オンデマンド取得 (Just-In-Time Fetching)**:
   - 全過去問を一括して事前保持せず、**ユーザーが特定の問題・大問に取り組む際、またはAIが問題の作成・出題・壁打ちを行うタイミングで、公式リソース（PDF等）から該当問題の情報をfetch（取得）して `assets/past-exams/<年度>/<大問>/` 配下のアセットを生成・拡張**します。
2. **アセットの完全性担保**:
   - 生成・拡張するアセット（`question.md`, `official_answer.md`）には、問題文の業務要件・関係スキーマ、IPA公式解答例、および採点講評（出題趣旨・受験者の誤答傾向）を正確に固定します。
3. **周回別ログの自動蓄積**:
   - 演習・壁打ち完了後は、周回番号（1周目/2周目/3周目）、ユーザー答案、自己採点、躓いた思考プロセス、AIからのフィードバックを `coaching_history.jsonl` に追記して永続記憶化します。これにより、セッションを跨いでも過去の弱点や克服経緯を途切れることなく参照できます。
