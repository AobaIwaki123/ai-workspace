# ADR-0002: ゲームより先にコード生成のテーマ表現を作る

## ステータス

採用

## 背景

アイドルをゲーム内の画像素材として扱う場合、素材ごとのトリミング、余白、色、状態差分、画面サイズへの対応が品質と実装量を押し上げる。ゲームジャンルを変えてもこの負担は残る。

また、現時点ではリズムゲーム、マージ、盤面パズルなどのジャンルを決めていない。特定ジャンルの画面を先に作ると、ゲーム選定とアート設計が結びつきすぎる。

## 決定

- ゲームジャンルを決める前に、SVG・CSS・JavaScriptでコード生成するテーマ表現を試作する。
- ツヨカワを、丸み・色・輪郭・記号・状態変化の組み合わせとして定義する。
- `idle`、`charge`、`power`、`recover` の状態を共通語彙にする。
- ゲームロジックはテーマレンダラーに状態だけを渡し、描画方法に依存しない構造を目指す。
- 画像素材は初期のゲームプレイに必須とせず、必要な場合は固定枠のコレクション等に限定する。

## トレードオフ

- コード生成だけでは、実在アイドルの個性や顔を直接表現しにくい。
- グループ固有性は、色・記号・言葉・状態ルールを一度設計する必要がある。
- SVGとCSSの表現を作り込むと、ゲーム実装前の設計コストが発生する。
- 一方で、素材の差し替え・画面ごとの手作業調整・権利依存を減らし、ジャンル変更に耐えやすくなる。
