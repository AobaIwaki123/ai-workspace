# Codex CLI 利用状況確認コマンドとレートリミット構造仕様

本ドキュメントは、OpenAI が提供するターミナル型 AI エージェント「Codex CLI」における利用状況確認コマンド（`/usage` および `/status`）の出力仕様、および 5 時間ローリング制限・週間上限・月次上限からなるレートリミット構造を整理した技術ノートです。

---

## 1. 利用状況確認コマンドの違い (/usage vs /status)

Codex CLI には利用状況を確認するスラッシュコマンドが 2 種類存在します。多くのユーザーが「現在の残り枠」を知る目的で `/usage` を実行して困惑しますが、両者の役割は明確に分かれています。

| コマンド | 表示対象 | 主な情報 | 用途 |
| :--- | :--- | :--- | :--- |
| **`/usage`** | **過去の実績・統計** | 累計消費トークン数、日別アクティビティ（草グラフ）、ピーク日、連続日数 | 利用傾向や過去の合計実績を振り返る |
| **`/status`** | **現在の残り枠・レート制限** | 直近 5 時間ローリング枠の消費率（%）、週間上限枠の消費率（%） | 今あとどれくらい作業を継続できるか確認する |

---

## 2. /usage コマンドの表示項目と見方

`/usage` を実行した際に出力される各指標の意味は以下の通りです。

```text
Lifetime tokens: 1,420,530
Peak day: 2026-09-28 (184,200 tokens)
Current streak: 4 days

Recent Activity:
[■■■ ■■  ■■■■] (日別ヒートマップ)
```

| 項目 | 説明 | 注意点 |
| :--- | :--- | :--- |
| **Lifetime tokens** | そのアカウント・環境で Codex CLI を通じて消費された**累計総トークン数**（Input + Output + Reasoning）。 | 残り枠ではなく「これまでに使った総量」を示します。 |
| **Activity Heatmap（草グラフ）** | GitHub のコントリビューショングラフに似た日別のアクティビティマップ。色の濃淡でトークン消費量の多さを表現します。 | 過去数週間から数ヶ月の利用頻度を視覚化します。 |
| **Peak day** | 過去最もトークン消費量が多かった特定日とそのトークン数。 | 大規模なリファクタリングや長時間の自動実行を行った日に記録されます。 |
| **Current streak** | 連続で Codex CLI を利用している日数。 | 開発の継続度合いを示すインジケーターです。 |

## 3. /status コマンドの表示項目と見方

現在利用可能なクォータや、あとどれくらいで制限に到達するかを把握するには **`/status`** を使用します。

```text
Status:
  5-hour rolling limit: [====>     ] 45%
  Weekly cap:           [==>       ] 20%
```

| 項目 | 周期と仕組み | 枯渇時の挙動 |
| :--- | :--- | :--- |
| **5-hour rolling limit** | **直近 5 時間のローリング制限枠**。<br>固定の時刻リセットではなく、5 時間前の消費分からスライディングウィンドウで順次回復します。 | 一時的にリクエストがブロックされます。5 時間前の消費トークンが時間経過とともに窓から外れることで再び利用可能になります。 |
| **Weekly cap** | **直近 7 日間（1 週間）の累積利用上限**。<br>過去 7 日間の合計消費量が上限に達していないかを判定します。 | 週間の上限に達した場合、5 時間枠に空きがあってもリセット期日（7 日前の利用枠回復）まで待機する必要があります。 |

> **仕様上の注意点**:  
> セッション開始直後で一度もプロンプトを送信していない状態では、サーバーとの間で利用状況が同期されず正しく表示されない場合があります。最低 1 回メッセージを送信した後に `/status` を実行してください。

## 4. Codex の制限体系（月次制限だけではない理由）

「Codex は月次上限（Monthly limit）だけなのか？」という疑問に対し、実際には利用契約形態（サブスクリプションか従量課金 API か）によって多層的な制限が設けられています。

### 4.1 サブスクリプション利用時 (ChatGPT Plus / Pro / Team 等)
日常的に CLI から ChatGPT アカウント認証で利用している場合、適用されるのは **5 時間ローリング枠** と **週間上限** の 2 つです。

* **5 時間ローリングウィンドウ (5-Hour Rolling Window)**:
  * 一番到達しやすいボトルネックです。
  * 固定の「毎正時リセット」ではなく、常に現在時刻から過去 5 時間分を遡って計算されます。
* **週間上限 (Weekly Cap)**:
  * 毎日のヘビーユースが重なった際に達するセーフティガードです。

### 4.2 API Key 従量課金利用時 (OpenAI Platform)
OpenAI Platform の API Key を設定して利用している場合、サブスクリプションとは異なる制限体系が適用されます。

* **Monthly Spending Limit（月間利用予算上限）**: 毎月の課金額の上限設定（月の初日にリセット）。
* **RPM (Requests Per Minute)**: 1 分あたりのリクエスト数制限。
* **TPM (Tokens Per Minute)**: 1 分あたりのトークン数制限。

### 4.3 トークンが急激に消費される要因
Codex CLI は単一のリクエスト・レスポンスではなく、自律エージェントとして以下を繰り返します。

1. プロンプト送信（システムプロンプト＋会話履歴）
2. 思考・推論（Reasoning）の実行（推論トークンの消費）
3. ファイル探索・コマンド実行・コード編集などのツール呼び出し
4. ツール結果の取得後、会話履歴全体を再送信して次のアクションを決定

このため、セッションが長引くほど毎回のリクエストサイズ（入力トークン数）が二次関数的に増大し、5 時間ローリング制限を急速に圧迫します。

## 5. Web ダッシュボードでの確認

CLI 外のブラウザ上から公式の制限状況を確認する URL は以下の通りです。

* **ChatGPT アカウント連携時**:  
  [ChatGPT Codex Usage Settings](https://chatgpt.com/codex/settings/usage)  
  現在のアカウントの利用上限、現在の使用パーセンテージ、リセット予測日時が確認できます。
* **OpenAI API Key 連携時**:  
  [OpenAI Platform Usage Dashboard](https://platform.openai.com/usage)  
  日別・月別の支出額、モデル別トークン内訳、残高クレジットが確認できます。

## 6. 消費を抑え制限を回避するための運用プラクティス

1. **セッションのこまめな分割 (`/new`)**:
   * 別タスクに移る際は、コンテキストを無駄に引き継がず `/new` でセッションを切り替えます。
2. **履歴の要約 (`/compact`)**:
   * 同一セッション内で作業を継続したい場合、`/compact` を実行して会話履歴を圧縮・要約し、入力トークンサイズを縮小します。
3. **推論エフォートの調整**:
   * 単純な調査や軽量な編集タスクでは過剰な深さの推論モデルを避け、タスクの難易度に応じた適切なモデル・設定を選択します。
