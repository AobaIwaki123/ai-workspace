# システム設計土台・基本方針マトリクス (06_architectural_foundations.md)

本ドキュメントは、Penlight Quiz v2 の根幹となる **6つの設計土台（デプロイ先、データ保持、データ追加性、開発容易性、マスタ拡張性、スキーマ把握性）** について、トレードオフを精査し、方針を確立するための基本設計書です。

---

## 1. どこにデプロイするのか (Deployment Target)

### 結論: 自宅 Proxmox k8s クラスタ (Cloudflare Ingress 経由)
パブリッククラウド（GCP / AWS 等）の高コスト・複雑な権限管理（IAM / Service Account）や廃止リスク（GCR 廃止等のレガシー負債）を完全排除し、**自宅インフラで自己完結** させます。

| 構成要素 | 採用技術 | 選定理由・特徴 |
|---|---|---|
| **実行基盤** | 自宅 Proxmox k8s クラスタ | リソース効率、常時稼働、既存 homelab 資産の最大活用 |
| **公開経路** | Cloudflare Tunnel / Ingress | 固定グローバルIP不要、DDNS不要、SSL/TLS自動終端、WAF保護 |
| **レジストリ** | GitHub Packages (`ghcr.io`) | GitHub Actions との親和性、無料枠、マルチアーキテクチャ対応 |
| **コンテナ構成** | **単一バイナリ統合 (Single Pod)** | Go 1.16+ `embed.FS` でフロントエンド（Next.js SSG / React ビルド成果物）を Go バイナリに内包。1 Pod (15〜30MB) で完結し、k8s マニフェスト・Service 設定を最小化 |

## 2. データはどう保つのか (Data Persistence & Durability)

### 結論: SQLite on PVC + Litestream (または GitOps マスタ二層構造)
クラウド DWH（BigQuery）や重厚な RDBMS（PostgreSQL 等）は不要。組み込み型 Pure Go SQLite（`modernc.org/sqlite`）を採用します。

### データ永続化の2大アプローチ比較

| 方式 | 概要 | メリット | デメリット | 採用方針 |
|---|---|---|---|---|
| **A: SQLite + PVC (PersistentVolumeClaim)** | k8s の CSI (Longhorn / NFS / Ceph) で SQLite ファイルを永続化 | 管理画面からの即時書き込みが可能 | クラスタ障害時のボリューム再アタッチやバックアップ運用が必要 | **管理画面即時更新を行うならこちら** |
| **B: GitOps ファイル正本 + 起動時 SQLite キャッシュ** | Git リポジトリ上の YAML/JSON/Markdown を正本とし、起動時に SQLite へ投入 | 履歴管理が Git で完全追跡可能。DB 破損リスクゼロ | データ更新に Git コミット / CI 再デプロイが必要 | **読み取り専用・Git レビュー重視ならこちら** |
| **C: ハイブリッド (SQLite on PVC + S3 リアルタイムレプリケーション)** | SQLite を PVC で動かしつつ、**Litestream** で MinIO/Cloudflare R2 に秒単位で非同期バックアップ | 管理画面での即時更新性と、障害時の即時リストアを両立 | Litestream の設定が1つ増える | **本番耐障害性を最大化する推奨案** |

## 3. データの追加の容易性 (Data Authoring & Operations)

### 結論: 「Web 管理画面（Admin UI）」と「GitOps（シード/バックアップ）」の両立
非エンジニア・スマホからでもペンライトカラーや新メンバーを追加できる手軽さと、データのバックアップ・履歴追跡の確実性を両立させます。

1. **Web 管理画面からの直接追加 (Day-to-day)**:
   - 認証付き管理画面（`/admin`）から、新メンバーやカラーをフォーム入力で即時登録・更新。
   - SQLite に即時反映され、クイズに即座に出題可能。
2. **エクスポート / インポート (GitOps 連携)**:
   - 管理画面から「現在のマスタを JSON/YAML として一括エクスポート」可能。
   - Git リポジトリにシードデータとしてコミットしておくことで、環境の再構築やローカル開発環境への流し込みが 1 コマンドで可能。

## 4. 開発容易性 (Developer Experience & AI Pair-Programming)

### 結論: 外部依存ゼロの「1 コマンド即起動」と「強い静的型付け」

1. **ローカル環境構築の容易性**:
   - クラウドサービス（BigQuery、Firebase、GCS 等）のエミュレータや認証 JSON ファイルは一切不要。
   - `modernc.org/sqlite` により Cgo（C コンパイラ）すら不要。
   - バックエンド: `go run ./cmd/server` だけで SQLite の自動マイグレーションと API 起動が完了。
2. **AI エージェント（協業）の効率最大化**:
   - Go はリフレクションや黒魔術的 ORM を多用せず、シンプルな明示的コードを好む言語であるため、AI のハルシネーション（嘘のコード生成）が極小化。
   - フロントエンドとの型同期は、Go 構造体から TypeScript 型定義（`d.ts`）をスクリプトで 1 秒生成。

## 5. メンバー、グループ、ペンライトカラー追加容易性 (Extensibility)

### 結論: スキーマ・コードの変更を一切行わない「完全動的マスタ」

「青葉坂46」のような新グループ誕生、新期生の加入、新色ペンライトの登場時に、**プログラムのソースコード修正やコンテナ再デプロイを一切不要** にします。

```
[Group Master (動的)] ──── (1:N) ──── [Member (動的)] ──── (2:N) ──── [Color Master (動的)]
  例: "青葉坂46"                        例: "青葉 太郎"                   例: "フォレストグリーン"
  slug: "aobazaka46"                   mem_0192...                       col_0192...
  theme: "#2E8B57"                     gen: 1                            hex: "#228B22"
```

1. **グループ追加**:
   - 管理画面から「青葉坂46」「スラッグ: `aobazaka46`」「テーマカラー: `#2E8B57`」を登録するだけで、フロントエンドのグループ選択タブに即時出現。
2. **カラー追加**:
   - 新色名と HEX コードを登録するだけ（グループ専用カラーか共通カラーかも指定可能）。
3. **メンバー追加**:
   - 氏名、期生、グループ、ペンライト左右カラーを選択し、写真をドロップするだけ。
   - 写真はバックエンドで `mem_<uuidv7>.webp` に自動リサイズ・WebP 変換して保存。

## 6. スキーマ把握容易性 (Schema Clarity & Source of Truth)

### 結論: Go 構造体を正本（Source of Truth）とした一元管理

ドキュメントとコードの乖離を防ぎ、人間・AI の双方が迷わないための規約です。

1. **Prefix Rule (TypeID 形式)**:
   - 全てのエンティティ ID は `grp_...`, `col_...`, `mem_...`, `quiz_...` のプレフィックスを持ち、ログや JSON を見た瞬間に何のデータか判別可能。
2. **自己文書化された Go 構造体 (`pkg/model`)**:
   - 必須/任意、JSON キー名、バリデーション制約（HEX コード形式、期生制約等）が構造体のタグおよびコメントとして 1 箇所に集約。
   - 曖昧な JSON サンプルの散乱を防止。
3. **スキーマ仕様書との完全同期**:
   - `note/05_schema_and_domain_specification.md` に設計根拠と制約一覧を記載し、Go 構造体コードへのリンク（`file://...`）で直結。

## 7. 設計土台マトリクスまとめ

| 観点 | 採用方針 | 狙い・効果 |
|---|---|---|
| **1. デプロイ先** | 自宅 Proxmox k8s + Cloudflare Ingress | クラウド費用ゼロ、GCR 等の廃止リスク排除、Go 単一バイナリ統合 Pod (15MB) |
| **2. データ保持** | Pure Go SQLite on PVC (+ Litestream レプリケーション) | 組み込み軽量、Cgo 不要、クラスタ内自己完結、秒単位バックアップ |
| **3. データ追加容易性** | Web 管理画面 + JSON/YAML シードインポート | スマホ・ブラウザから即時入力可能、Git による履歴追跡・環境複製も容易 |
| **4. 開発容易性** | 外部依存ゼロ（`go run` のみ）、Cgo 不要、Go + TS 型生成 | クラウド認証不要、セットアップ 1 分、AI ペアプロでのコード生成精度最大化 |
| **5. メンバー等追加容易性** | Enum 排除、完全動的リレーショナルマスタ | 青葉坂46 や新色追加時にコード変更・再ビルド不要 |
| **6. スキーマ把握容易性** | Prefix Rule (`grp_`, `col_`, `mem_`) + Go Struct 正本 | 人間・AI ともに ID の種類・データ構造・制約を迷わず即時理解 |
