# チャット対話向けプロンプトチューニングと応答レイテンシ最適化

本ドキュメントは、Antigravity CLI (`agy`) をチャットプラットフォーム（Discord、Slack、Teams 等）のバックエンドとして活用する際、デフォルトの長文レポート出力を抑制し、チャットに最適化された要約応答と低遅延（高速化）を実現するためのプロンプトチューニング設計をまとめた技術ノートです。

---

## 1. チャット UI における課題

Antigravity の標準モデルは、コードベースの詳細な調査や堅牢なシステム設計レポートを生成するよう最適化されています。
そのため、チャットツールからプロンプトをそのまま渡すと以下の問題が発生します:

1. **過剰な情報量と長大なテキスト**:
   - 挨拶や前置き、背景説明、マークダウン表が大量に出力され、チャットの画面が埋め尽くされる。
2. **文字数制限の超過**:
   - Discord の 1 メッセージ上限（2,000 文字）を容易に突破し、複数通に分断されて読みにくくなる。
3. **推論レイテンシ（待ち時間）の増大**:
   - 推論エフォート（Thinking）が深いため、回答が生成されるまでに 20〜40 秒以上かかり、会話のリズムが損なわれる。

---

## 2. 解決策: チャット制約ラッパーの自動注入

Bot や API サーバーの入力層において、ユーザーのプロンプトを透過的に以下の制約文でラップして `agy` に渡します。

```text
[Discordチャット用の回答制約]
Discordでのチャット会話です。
- 長文レポートや冗長な前置きは禁止します。
- 要点を2〜5行程度の簡潔な箇条書きまたは短い文章で回答してください。
- 必要最小限の情報（結論、重要な数値・日時・URLなど）のみを伝えてください。

【指示】
<ユーザー入力>
```

### 適用効果の比較

| 項目 | ラッパー適用前 (デフォルト) | ラッパー適用後 |
| :--- | :--- | :--- |
| **出力長** | 1,500 〜 3,500 文字 (複数通に分割) | 150 〜 500 文字 (1 通で完結) |
| **前置き / 挨拶** | 長大な前置きと結びの挨拶が含まれる | 結論先行、即座に要点のみを箇条書きで提示 |
| **可読性** | スクロールが必要 | スマホ画面でも 1 画面に綺麗に収まる |

---

## 3. 推論エフォート (`--effort`) によるレイテンシ最適化

`agy` には推論の思考深度を制御する `--effort` フラグが用意されています。

| エフォート値 | 思考時間 (Thinking) | 応答時間目安 | チャット適性 | 特徴 |
| :--- | :--- | :--- | :--- | :--- |
| **`low` (推奨)** | 最小限 | **2 〜 8 秒** | **最適** | 挨拶、質問応答、既知の要約、クイックな指示に最適。 |
| **`medium`** | 標準 | 8 〜 15 秒 | 普通 | 複数スキルの選定や簡単なコード確認。 |
| **`high`** | 深い思考 | 15 〜 40 秒 | 重い処理向け | 複雑なリファクタリングやアーキテクチャ設計時のみ指定。 |
| **`max`** | 最大思考 | 40 秒以上 | バッチ専用 | 対話チャットには不向き。 |

チャット Bot においては、デフォルト値を `--effort low` に設定し、ユーザーがスラッシュコマンドのオプション等で明示的に指定した場合のみ `high` や `max` に昇格させる設計が実用的です。
