# ADR-0003: mise による言語ランタイム・CLIツールの宣言的管理の採用

## ステータス

承認 / 適用中 (Accepted)

---

## コンテキスト (背景と課題)

WSL サーバー上で開発・運用を行うにあたり、Node.js, Go, Python, GitHub CLI (`gh`), `jq`, `ripgrep` 等の多種多様なツールが必要となります。
従来の手動手順（`apt install`, `curl | bash`, バージョン固定の手動ビルド等）では以下の課題が存在していました：

1. **再現性の欠如と手順の長大化**: マシンが変わるたびに大量のコマンドを叩く必要があり、コピペミスやバージョン差異が発生する。
2. **システム環境（`/usr/bin`）の汚染**: OS 提供のパッケージと開発用ランタイムが混在し、ライブラリの競合やアップグレード時の破壊が発生しやすい。
3. **バージョンの宣言的管理の難しさ**: プロジェクトやチームで同じバージョンを揃えるのが困難。

---

## 意思決定 (Decision)

言語ランタイムおよび主要 CLI ツールの管理に **[`mise`](https://mise.jdx.dev/)** を採用し、設定ファイル **`mise.toml`** による完全宣言的管理を行う。

### 構成方針
- リポジトリ直下に `wsl-server/mise.toml` を配置。
- ツール導入は `wsl-server/scripts/setup-mise.sh` または `mise install` の 1 コマンドで完結。
- ツール群は `~/.local/share/mise`（ユーザー空間）にインストールされ、システム OS 領域を変更しない。

---

## 結果と影響 (Consequences)

### メリット (Positive)
- **ワンコマンドでの全ツール導入**: `mise install` だけで Node.js, Go, Python, gh, jq, ripgrep 等が自動的に一括導入される。
- **高速かつ安全**: Rust 製のためオーバーヘッドが極小で、システムの apt パッケージに依存せずクリーンな状態を維持できる。
- **Git によるバージョン管理**: `mise.toml` を Git 管理することで、サーバー環境のツール構成をコードとしてバージョン管理・共有できる。

### デメリット・留意点 (Negative / Risks)
- シェルの起動時に `eval "$(mise activate ...)"` が必要（`setup-mise.sh` にて `~/.bashrc` / `~/.zshrc` へ自動組み込み）。
