# WSL サーバー構築 要件定義 & アーキテクチャ設計 (note/01)

## 1. 概要

本ドキュメントは、Windows マシン上の WSL2（Windows Subsystem for Linux）を活用して開発用・検証用・常時稼働用サーバーを構築するための要件定義、技術選定、および設計上の論点を整理したものです。

---

## 2. 目的・背景

- Windows マシンの遊休リソースや開発用 PC を活用し、Linux ベースのサーバー環境を構築する。
- 物理マシンのデュアルブートや別 PC の用意を不要とし、Windows のデスクトップ環境と共存させながら Linux サーバーを常時またはオンデマンドでバックグラウンド稼働させる。
- 最終成果物として、ゼロから再現可能な「WSL サーバー構築 統合手順書（Runbook）」を完成させる。

---

## 3. 要件一覧

### 3.1 機能要件
1. **Linux OS 稼働**:
   - Ubuntu 24.04 LTS または 22.04 LTS を WSL2 上で安定稼働させる。
2. **systemd のサポート**:
   - `/etc/wsl.conf` で `systemd=true` を設定し、各種デーモン（sshd, docker, cron, nginx 等）を systemctl で管理可能にする。
3. **リモートアクセス（SSH）**:
   - Windows ホスト自身および同一 LAN 内の他端末（Mac / 他 PC / スマホ等）から SSH 鍵認証でアクセス可能にする。
4. **自動起動（バックグラウンド常駐）**:
   - Windows 起動時（ログオン時またはブート時）に WSL インスタンスおよび必要なバックグラウンドサービスが自動で立ち上がるようにする。
5. **ネットワーク公開**:
   - 外部・LAN から WSL 上で動作する Web/API サービス（ポート 80, 443, 3000, 8080 等）にアクセスできるようにする。

### 3.2 非機能要件
1. **リソース制御**:
   - Windows ホスト側のメモリ枯渇を防ぐため、`.wslconfig` により WSL が消費する最大 CPU コア数・メモリ・スワップサイズを明示的に制限する。
2. **ストレージ性能と整合性**:
   - サーバーデータおよびコードは Windows ファイルシステム（`/mnt/c/...`）ではなく、WSL 内のネイティブ Linux ファイルシステム（`/home/...` または `/var/...`）に配置して I/O パフォーマンスとファイルパーミッション整合性を担保する。
3. **セキュリティ**:
   - SSH のパスワード認証を禁止し、公開鍵認証のみを許可する。
   - 不要なポートの露出を抑え、ファイアウォール（Windows Defender / Linux UFW）を適切に構成する。

---

## 4. アーキテクチャと設計上の主要な論点

### 4.1 ネットワークモードの選定 (NAT vs Mirrored Mode)

WSL2 には主に2種類のネットワーク構成が存在します。

| 項目 | NAT モード (従来型 / デフォルト) | Mirrored モード (WSL 2.0+ / Windows 11 推奨) |
| :--- | :--- | :--- |
| **IP 体系** | WSL が独自の仮想サブネット IP（毎回変動）を持つ | Windows ホストの IP アドレス（LAN IP）をそのまま共有 |
| **LAN からの接続** | `netsh interface portproxy` によるポート転送が必要 | ポート転送不要。Windows のファイアウォール開放のみで直結可能 |
| **IPv6 対応** | 制限あり | 完全対応 |
| **要件** | Windows 10 (2004+) / Windows 11 | Windows 11 (22H2 22621.2361+) |
| **推奨** | レガシー環境・Win10 向け | Windows 11 環境であれば Mirrored Mode を強く推奨 |

### 4.2 Windows 起動時の自動起動方式

WSL は通常、ターミナルを開くかコマンドを実行したときにオンデマンドで起動し、放置するとシャットダウンすることがあります。サーバーとして稼働させるための方式を検討します。

1. **方式 A: Windows タスクスケジューラ + `wsl.exe` バックグラウンド起動**
   - Windows ログオン時（またはシステム起動時）に `wsl.exe -d <distro> -u root --exec /bin/true` や `wsl.exe -d <distro>` をバックグラウンド実行。
   - systemd 有効化環境であれば、これだけで systemd が立ち上がり、enabled なサービスが自動起動する。
2. **方式 B: Windows サービス化 (NSSM 等)**
   - ユーザーログオン前（PC 起動直後）から常時稼働させたい場合に有効。
