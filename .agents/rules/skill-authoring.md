# Skill Authoring & Quality Review Rule

本ルールは、`.agents/skills/` 配下のスキルファイル（`SKILL.md`, `scripts/`, `references/` 等）を作成または編集する際に自動的に適用されるレビュー基準およびガイドラインです。

エージェントは、スキルを作成・変更した際に必ず以下の観点でセルフレビュー（自己検証）を行い、品質基準を満たしていることを確認してください。

---

## 1. セルフレビュー・チェックリスト

### A. YAML Frontmatter（最重要）
- [ ] **`name`**: 一意な識別子であり、英小文字とハイフンのみ（kebab-case）で命名されているか。
- [ ] **`description`**:
  - 3人称（"Detects...", "Reviews...", "Use this skill when..."）で記述されているか。
  - **What（何をするか）**だけでなく、**When（どんなキーワード・プロンプト・状況で発動すべきか）**が具体的に明記されているか。
  - エージェントが誤爆（関係ないプロンプトでの過剰発動）や不発を防げる適切な解像度になっているか。

### B. 段階的情報開示（Progressive Disclosure）
- [ ] **`SKILL.md` の簡潔さ**: メインファイルが長大化（トークンの過剰消費）していないか。
- [ ] **補助ディレクトリの活用**:
  - 詳細な仕様・長文リファレンスは `references/` に分離し、`SKILL.md` からリンクしているか。
  - 再利用可能なスクリプトは `scripts/` に分離しているか。
  - 必要に応じて `examples/`（実例）や `resources/`（テンプレート）を設けているか。

### C. 実行可能スクリプト（Executable Helpers）
- [ ] 複数行の複雑なコマンドやパイプライン処理は `scripts/` 配下にスクリプト化されているか。
- [ ] スクリプトに実行権限（`chmod +x`）が付与され、エラーハンドリング（`set -euo pipefail` 等）が記述されているか。

### D. 検証ループ（Verification Loop）
- [ ] 手順の末尾に、実行結果や成功を検証するステップ（テスト、ログ確認、`git diff`、dry-run等）が含まれているか。

### E. 重複の排除（No Duplication）
- [ ] 一般的なプログラミング知識や既知の基礎事項（LLMが知っている一般的な概念）を長々と解説していないか。

---

## 2. 自動レビューと修正アクション

スキルの作成・編集を完了する前に:
1. `validate-skill.sh`（または同等の検証スクリプト）を実行して構文・構成チェックを行う。
2. チェックリストに違反している点があれば、即座に修正した上でユーザーに報告する。
